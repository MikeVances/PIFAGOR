

# 🧠 PIFAGOR — Poultry Intelligence Framework & Archive of Organizations and Resources

PIFAGOR — это индустриальная система сбора, классификации и структурирования данных о предприятиях птицеводства.  
Главная задача — превратить огромное количество разрозненных карточек, PDF, фото, справочников и мини‑баз в единую цифровую систему знаний, доступную людям, ботам и LLM‑агентам.

---

## 🎯 Миссия проекта

Создать **единый реестр птицеводческой индустрии**, с возможностью:
- быстро находить предприятия,
- понимать структуру холдингов,
- видеть контакты, роли, филиалы,
- обеспечивать автоматическую аналитическую надстройку,
- давать данные в формате API/JSON для других компаний, агентств, интеграторов,
- формировать основу для новостной и исследовательской платформы.

PIFAGOR = **Poultry Intelligence Framework Archive of Organizations & Research**

---

## 🏗 Что делает система (MVP — текущий этап)

1. **Берёт карточки предприятий** (фото из старых справочников, JPG стопками).
2. **Автоматически классифицирует** по типу предприятия:
   - broiler  
   - pullets  
   - parent_stock  
   - hatchery  
   - egg  
   - feed_mill  
   - processing  
   - mixed  
3. **Извлекает данные из карточки**:
   - холдинг/группа, юрлицо и конкретная площадка (с адресами),
   - контакты площадки (ФИО, роль, телефоны, e-mail),
   - веб‑сайты и текстовое описание логотипов.
4. **Формирует структурированный JSON** в формате «holding → company → site».
5. **Сохраняет данные в базу**: холдинги, компании, площадки, контакты, сайты, исходные JSON, юридическое обогащение.

## 🔄 Текущий конвейер

### 1. Очереди файлов

- **Папки:** `incoming_photos` (новые карточки), `actions_in_progress` (обрабатывается), `archive_photos` / `error_photos`.
- **Сервис `card_queue`** (`services/worker/card_queue.py`) управляет файлами: `push_next_card()` переносит первую карточку из incoming в in_progress и возвращает имя; `mark_card_processed()` архивирует файл (или отправляет в ошибки) и автоматически подтягивает следующий.

### 2. HTTP/API слой

- `services/api/gpts_actions_server.py` объединяет все эндпоинты:
  * `POST /pifagor/push_next_card` → выдаёт `filename` и `file_url` карточки.
  * `GET /pifagor/files/<filename>` → отдаёт само изображение (через ngrok доступно GPT).
  * `POST /pifagor/submit_card_result` → принимает `{filename, result}`; после записи в БД вызывает `mark_card_processed`, архивирует файл и ставит следующий.

### 3. Работа GPT-агента

1. Оператор пишет «Поработай». Агент вызывает `pushNextCard`, получает ссылку и имя файла.
2. Агент скачивает изображение, выполняет OCR, формирует JSON по схеме PIFAGOR.
3. Агент вызывает `submitCardResult` (обязательно включает `filename`).
4. Backend записывает компанию в `pifagor.db`, переносит файл в архив и разворачивает следующую карточку. Агент коротко сообщает оператору («Обработано: ...»).

### 4. Хранилище и база данных

- `services/db_writer/db_writer.py` теперь работает с иерархией: `holdings` → `companies` → `sites`, хранит контакты площадок, описания логотипов (`logo_hint`), ответы ФНС (`company_legal_enrichment`) и raw JSON.
- Каждая запись хранит:
  * Холдинг: название, ИНН, родитель, текстовое описание логотипа.
  * Компания: юрлицо (название, ИНН, продукция, адрес, связь с холдингом).
  * Площадка (site): имя, тип, адрес, контакты, сайты, `logo_hint`.
  * `results_raw`: история исходных JSON с `company_id` и `site_id`.
  * `company_legal_enrichment`: кэш ответов API ФНС.

Такой файловый конвейер уже полностью работает локально: достаточно запустить `./starter.sh` и пробросить порт `7001` через ngrok.

## 🗂 Структуры данных (ключевое)

### Holding
- id, name, inn, parent_holding_id  
- logo_hint — текстовое описание логотипа/бренда  

### Company
- id, holding_id, name, inn  
- production_type.primary  
- address_full, region, district, locality

### Site
- id, company_id, name, site_type  
- адресные поля, websites[]  
- logo_hint — описание логотипа площадки  
- contacts[] (site_contacts + phones, emails)

### Task / Result
- task → file_path, status  
- result → JSON, company_id, site_id, timestamp

## 🧩 Почему это важно

Отрасль птицеводства огромная, но крайне «бумажная».  
PIFAGOR впервые создаёт **цифровой фундамент** индустрии, который можно использовать:
- интеграторам оборудования,
- дистрибьюторам,
- СМИ,
- аналитическим агентствам,
- ветеринарам и технологам,
- разработчикам IoT / мониторинга.
